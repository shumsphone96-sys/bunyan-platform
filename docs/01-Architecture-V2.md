# BUNYAN V2 Architecture

## الهدف
إعادة بناء واجهة الإدارة بصورة مستقلة ومستقرة، مع الحفاظ على الخادم الحالي وقاعدة البيانات حتى يكتمل الاختبار.

## مصدر الحقيقة
- واجهة الإدارة الجديدة: `admin-v2/`
- ملف HTML واحد: `admin-v2/index.html`
- ملف CSS واحد: `admin-v2/styles.css`
- ملف JavaScript واحد: `admin-v2/app.js`
- الخادم الحالي: `backend/`
- قاعدة البيانات الحالية تبقى دون تعديل خلال Sprint 1.

## قواعد إلزامية
1. يمنع تحميل ملفات الإدارة القديمة داخل `admin-v2`.
2. يمنع ربط الزر نفسه من أكثر من ملف.
3. يمنع النشر المباشر على `main` قبل نجاح GitHub Actions واختبار القبول اليدوي.
4. كل مسار API محمي يجب أن يرجع 401 دون Token.
5. الجلسة الإدارية تحفظ في مفتاح واحد فقط: `bunyan_v2_token`.
6. لا توجد قائمة موقع عامة داخل لوحة الإدارة.
7. لا يضاف قسم جديد قبل نجاح دورة القسم السابق: قراءة، تعديل، حفظ، إعادة تحميل.
8. أي خطأ اتصال يظهر للمستخدم بوضوح ولا يخفي الصفحة.

## حدود Sprint 1
- تسجيل الدخول.
- التحقق من الجلسة.
- تسجيل الخروج.
- لوحة المؤشرات.
- طلبات المساعدة.
- طلبات المشاركة.
- تغيير حالة الطلب وحفظها.

## ما لا يدخل في Sprint 1
- إعادة تصميم الخادم.
- ترحيل قاعدة البيانات.
- دمج الواجهة مع الموقع الرسمي.
- إضافة ميزات جديدة غير مختبرة.

## بوابة الاعتماد
لا يصبح Pull Request جاهزًا للدمج إلا بعد:
- نجاح `Admin V2 Quality Gate`.
- اختبار الدخول بحساب حقيقي.
- ظهور الطلبات الحقيقية.
- تغيير حالة طلب وحفظها.
- تحديث الصفحة وبقاء الحالة الجديدة.
- نجاح تسجيل الخروج.
- اختبار الهاتف والكمبيوتر.
